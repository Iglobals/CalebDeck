## Root cause (shared by issues 1–3)

Every Fashion order is pre-saved to Firestore by `api/pre-save-order.ts`, which has **no Fashion branch** — its terminal `else` (line 299) writes an empty Food "plates" doc with no `type`, no `orderType`, no `deliveryFee`, no `items`. After payment, `api/verify-payment.ts`'s pre-saved fast-path (lines 224–234) only flips status to PAID and **never back-fills those fields**, so the doc stays plate-shaped forever. The customer side looks correct because checkout navigates to OrderSuccess with in-memory state (`orderType: 'FASHION'`), but every cold Firestore read — admin pages, Order History tracking, fee recomputes — sees a Food-shaped doc. Aggravators: Paystack `config.metadata` omits orderType (webhook mis-detects), all server Mart checks are lowercase while `MartCheckout` sends `'MART'`, the ₦1250 premium has no fashion guard, and `verifyFunding` exists as two identical copies.
